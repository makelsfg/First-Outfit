# First-Outfit · 小白穿衣推荐

> 给曾经和我一样，不知道穿什么才不出错的你。

## 这是什么

一个面向**穿衣小白**的微信小程序。

如果你刚上大学，因为家庭或成长环境的原因，没有接触过基础的穿衣知识，不知道什么天气穿什么、什么场合穿什么才不出错——这个小程序就是为你做的。

它不教你变时尚，不让你学搭配理论。它只做一件事：

**告诉你今天穿什么，不会出错。**

## 为什么做这个

我大一的时候，也不知道怎么穿衣搭配。

不是不想学，是没有人教，也不好意思问。穿多了热，穿少了冷，去面试怕穿得太随意，去上课又怕穿得太奇怪。衣柜里衣服不少，但总觉得没衣服穿。

后来慢慢试、慢慢看，才明白穿衣搭配没有想象中那么难。它不需要天赋，只需要有人告诉你几条最基础的规则。

所以我想做一个工具，帮助像曾经的我一样的人。

## 现在能用的功能

> 下面只写代码里真实接通的入口，没接通的在下一节单独列出。

### 1. 今日推荐（首页 · tab）

- **真实天气**：定位 → 云函数 `getWeather`（高德 Key 在服务端）→ 当地实时温度、体感、天气现象、风力、当日最高/最低。预报拿不到也不影响：按月份退回四季兜底（春 18℃ / 夏 29℃ / 秋 19℃ / 冬 5℃）。
- **三个时段**：现在 / 今天 / 明早。「今天」「明早」用气温区间中位数当温度锚点，而不是实时温度。
- **五个场合**：日常 / 约会 / 运动 / 聚会 / 正式，切换只影响本次推荐，不写回设置。
- **三套方案可循环**：每个「温度带 × 场合」给 3 套（`outfitRules.ts` 的 `VARIANT_COUNT`），按「目标厚薄」与当天最接近的排第一并标「推荐」，其余标「更保暖 / 更轻便 / 换个样式」，按钮是「换一套（x/3）」。
- **一套里有什么**：上装 / 内搭 / 外套 / 下装 / 鞋子 + 一句话结论 + 「为什么这样穿」逐条理由 + 天气提醒（带伞、大风、早晚温差、防晒）。
- **形象图随性别变**：设置里选「女 / 男 / 不透露」，首页显示对应的女孩 / 男孩 / 小熊图（`images/avatar-*.png`，由 `tools/prepare-avatars.py` 生成）。
- **衣柜轻打通**：推荐时优先用你衣柜里「厚薄合适 + 场合匹配」的单品，文案标注「（你衣柜里的）」；厚薄明显不合适则给一句劝退而不是硬塞。
- **城市可手动选**：省 → 市两级弹层，定位被拒也能用。
- **自动刷新**：页面在后台超过 10 分钟再回来会重新取天气（`AUTO_REFRESH_MS`）。
- **入口**：右下角悬浮 💬 进客服问答。

### 2. 我的衣橱（tab）

- 衣物字段：分类（上装 / 外套 / 下装 / 鞋子 / 配饰）、名称、季节、颜色、材质、标签（日常 / 休闲 / 正式 / 运动 / 约会 / 聚会 / 居家 / 户外）、备注、照片（存云存储）。
- 支持增 / 删 / 改 / 查，列表上限 200 条；搜索框模糊匹配名称、类目、颜色、材质、标签，另有分类计数筛选。
- 编辑时**只有换图才重新上传**，并删掉旧图，避免云存储堆积。
- 轻打通打分（`utils/wardrobe.ts` 的 `pickWardrobe`）：厚薄差 ≤1.2 才可用，命中场合标签 +2、命中季节 +1、命中不上减分，得分 ≥1 才采用。

### 3. 客服问答（首页悬浮入口进）

- **真流式输出**：提问后先出「正在思考…」，模型一开始返回就逐字冒出来，末尾闪光标，长回答自动追底。实现是「云函数写库 + 客户端 `db.watch()`」——`wx.cloud.callFunction` 本身拿不到流式响应。
- **每轮可收起**：回答下方「收起 ▴」，一点就把这一轮的问 + 答折成一行「问：xxx 展开 ▾」，长对话不再刷屏。
- **对话会保留**：本地存最近 **120 条**消息，退出再进来还在；顶部「清空对话」二次确认后清空。
- **降级不炸**：`llm_stream` 集合缺失、`watch` 失败、云函数没升级等情况，会自动退回「整段返回 + 打字机逐字显示」，任何环境都能出字；整体 45 秒超时，中断时保留已生成的部分。
- **话题与性别边界**：系统提示词限定只回答穿衣搭配相关问题，其余话题礼貌拒绝并引回穿搭；男性 / 未透露性别不推荐裙装类单品。

### 4. 设置（tab）

- 昵称、性别（男 / 女 / 不透露）、年龄段（18 岁以下 / 18-24 / 25-34 / 35-44 / 45 岁以上）、默认场合、怕冷程度（怕冷 / 正常 / 怕热）、出行方式（驾车 / 步行 / 骑行）、防雨防滑（自动 / 保守 / 轻量）、主题色（浅蓝 / 粉色 / 暖橙）。
- 选性别会连带推荐默认主题色（女→粉、男→蓝、不透露→橙），也可手动改；保存后首页 `onShow` 自动生效（形象图、主题、场合）。

## 还没接上的部分（代码在，入口没有）

这几块服务层和云函数都写好了，但页面上没有入口。**1.5 的版本描述已确认不含「每日打卡」和「风采库」两项**，代码保留待后续版本接入：

| 能力 | 现状 |
|---|---|
| 每日穿搭打卡 | `utils/checkin.ts` 服务完整（同日去重、上限 100 条、批量删除），`checkin_records` 集合就绪，但**首页没有任何打卡按钮**，`addCheckin / hasCheckedToday / countCheckinDays` 无调用方 |
| 个人风采库 | `pages/gallery` 瀑布流 + 管理批量删除可用，但**全仓没有跳转入口**；空态文案还写着「快去记录今日穿搭」 |
| 意见反馈 | `cloudfunctions/submitFeedback` + `feedback` 集合就绪；首页原来只有个「点击反馈」的占位提示，已在 1.5 移除入口，等做输入弹窗时再接 |
| 鼓励语文案 | `encouragement_library` 集合 + 内置 10 条兜底，无调用方（设置页底部是硬编码的一句话） |

## 设计原则

- **不评判**：不问「你怎么连这个都不知道」，而是说「很多人一开始都不懂，这很正常」。
- **给兜底**：不确定的时候永远有一个最简单安全方案（天气拿不到按季节推算，定位被拒可手动选城市，流式不可用就退成整段返回）。
- **解释为什么**：不只给结果，还告诉你「为什么这样穿不会错」。
- **极简**：没有登录、没有社交、打开即用。**穿什么由确定性规则决定**，不是让 AI 替你决定穿搭。
- **性别是硬边界**：性别选「男」或「不透露」时，规则引擎和衣柜轻打通都不会给出裙子、半身裙、打底袜 / 打底裤、玛丽珍鞋等女装单品；只有明确选「女」才启用女装覆盖。数据层（`OUTFITS` 的 `female` 覆盖）与运行时（`genderSafe()` 过滤 + 兜底款）双重保证，`tools/test-outfit-gender.mjs` 会逐套断言。

## 技术栈

- 微信小程序原生开发 + TypeScript（开发者工具基础库 3.17.4）
- 后端：微信云开发（云函数 + 云数据库 + 云存储），无自建服务器
- 天气：高德开放平台（定位逆地理编码 + 实况 + 预报），经云函数 `getWeather` 代理
- 大模型：阿里云百炼 DashScope（OpenAI 兼容接口，默认 `deepseek-v4.1-flash`），经云函数 `askLLM` 代理，支持 `stream: true`
- 流式：客户端建 `llm_stream` 临时文档 + `db.watch()`，云函数边解析 SSE 边节流写回累积文本
- 本地缓存：个人信息、所选城市、客服对话（其余记录走云端）

## 前后端划分

| 层 | 位置 | 职责 |
|---|---|---|
| 前端 | `miniprogram/` | 页面渲染、穿搭规则引擎、数据服务封装 |
| 后端 | `cloudfunctions/` + 云开发 | 第三方 API 代理（隐藏密钥）、数据持久化、流式中转 |

**数据流**：

- 天气 → 云函数 `getWeather`（高德 Key 在服务端）
- 穿搭推荐 → 前端 `outfitRules.ts` **本地计算**（不依赖网络，离线可用）
- 衣柜 → 云数据库 `wardrobe_items` + 云存储 `wardrobe/` 前缀的图片
- 客服问答 → 云函数 `askLLM`；流式时增量写入 `llm_stream`，客户端 `watch` 渲染，结束后删除文档
- 打卡记录 → `checkin_records`（仅风采库读取 / 删除，无新增入口）
- 反馈 → 云函数 `submitFeedback` → `feedback`（前端暂无调用）
- 个人信息、所选城市、客服对话记录 → 本地存储

**云数据库集合**（`initData` 的 `COLLECTIONS` 会自动创建）：

| 集合 | 用途 | 建议权限 |
|---|---|---|
| `wardrobe_items` | 衣柜衣物 | 仅创建者可读写 |
| `checkin_records` | 打卡记录 | 仅创建者可读写 |
| `llm_stream` | 客服流式中转（用完即删） | 仅创建者可读写 |
| `encouragement_library` | 鼓励语库 | 所有用户可读 |
| `feedback` | 用户反馈 | 仅创建者可读写 |

## 运行说明

1. 安装「微信开发者工具」：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
2. 「导入项目」，目录选 `项目-小白穿衣推荐`（含 `project.config.json` 这一层）
3. 开通云开发：点「云开发」→ 创建环境，把环境 ID 填到 `miniprogram/utils/config.ts` 的 `CLOUD_ENV`
4. 部署 4 个云函数：右键 `cloudfunctions/` 下的 `initData`、`getWeather`、`askLLM`、`submitFeedback` →「**上传并部署：云端安装依赖**」，**一次只传一个**，等上一个显示成功再传（并发会报 `FailedOperation.UpdateFunctionCode: 当前函数处于Updating状态`）
5. 配置环境变量（云开发控制台 → 云函数 → 对应函数 → 配置）：
   - `getWeather` → `AMAP_KEY`：高德「Web 服务」类型 Key
   - `askLLM` → `DASHSCOPE_KEY`：阿里云百炼 Key（可选 `LLM_MODEL` 覆盖模型名），并**把超时时间从默认 3 秒改成 60 秒**（流式要占满整个生成过程）
6. 数据库权限：按下表设置；`llm_stream` 由客户端建文档、云函数以管理员身份写入，**不要**改成「所有用户可读」
7. 定位权限：`getLocation` 需在小程序后台申请「地理位置」接口权限；未申请或未授权时自动引导手动选城市（`app.json` 已声明 `requiredPrivateInfos`）
8. 编译运行：`app.ts` 启动时会静默调用 `initData` 建集合与写入鼓励语（幂等，失败不影响使用）

## 客服流式问答：部署与排错

链路：小程序 `add` 一条 `llm_stream` 文档 → `doc().watch()` → 调用 `askLLM`（带 `streamId`）→ 云函数 `stream: true` 逐段解析 SSE 并节流写库（首包立即写，之后每 400ms 或每新增 80 字写一次）→ 客户端收到推送刷新气泡 → 结束后删除文档。

| 现象 | 原因 | 处理 |
|---|---|---|
| 日志 `[llm] stream doc unavailable` | 集合不存在 / 权限不对 | 重新部署 `initData`，确认 `llm_stream` 存在且为「仅创建者可读写」 |
| 日志 `[llm] watch error` | watch 连接失败（基础库 < 2.8.1 / 网络） | 已自动降级为整段返回 + 打字机 |
| 云函数日志 `stream write failed` | 云函数写库失败 | 缺集合，或云函数与数据库不在同一环境 |
| 完全没回答 | `askLLM` 超时还是 3 秒 | 改成 60 秒并重新部署 |
| 回答整段一次性出现 | 走了降级路径 | 按上面几行逐个排查，功能仍可用 |

## 控制台常见提示怎么读

| 控制台输出 | 是什么 | 要不要处理 |
|---|---|---|
| 「基础库从 3.7.0 起正式支持 HarmonyOS…」 | 开发者工具的基础库更新提示 | 不用改代码；真要适配鸿蒙用 `wx.getDeviceInfo()` 取平台 |
| `[Perf] App.onLaunch took 54ms` | 启动耗时统计 | 不用处理 |
| `routeDone with a webviewId ... is not found` | 路由层收到完成回调时 webview 已不存在，常见于编译热重载、连点跳转、页面销毁后返回 | 重编译即消失属工具噪声；所有跳转已统一走 `utils/nav.ts` 防护 |
| `FailedOperation.UpdateFunctionCode: 当前函数处于Updating状态` | 上一次部署还没结束 | 等 1~3 分钟，一次只传一个函数 |

## 已知限制

- 云开发为付费服务，免费额度有限；流式问答每次约产生 5~20 次数据库写（已刻意节流）
- 客服对话记录存**本地**（换设备 / 清缓存会丢），只保留最近 120 条
- 打卡与风采库当前**没有入口**，1.5 版本描述已不含这两项；页面与云函数代码保留，后续接入时再补入口
- 定位接口权限未批时，手动选择城市是官方兜底路径；城市数据覆盖 34 个省级行政区的主要城市
- 天气与大模型 Key 只存在云函数环境变量里，前端不含任何密钥
