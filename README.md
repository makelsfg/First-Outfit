# First-Outfit · 小白穿衣推荐

> 给曾经和我一样，不知道穿什么才不出错的你。

## 这是什么

一个面向**穿衣小白**的微信小程序。

如果你刚上大学，因为家庭或成长环境的原因，没有接触过基础的穿衣知识，不知道什么天气穿什么、什么场合穿什么才不出错——这个小程序就是为你做的。

它不教你变时尚，不让你录入衣橱，不让你拍照识衣。它只做一件事：

**告诉你今天穿什么，不会出错。**

## 为什么做这个

我大一的时候，也不知道怎么穿衣搭配。

不是不想学，是没有人教，也不好意思问。穿多了热，穿少了冷，去面试怕穿得太随意，去上课又怕穿得太奇怪。衣柜里衣服不少，但总觉得没衣服穿。

后来慢慢试、慢慢看，才明白穿衣搭配没有想象中那么难。它不需要天赋，只需要有人告诉你几条最基础的规则。

所以我想做一个工具，帮助像曾经的我一样的人。

## 核心功能

### 1. 今日推荐（首页）

打开就能看到：

* 所在城市的**真实天气**：实时温度、体感温度、天气现象、季节，以及**当天最高 / 最低温**
* 一套**个性化**穿搭方案：结合天气温度与你的**性别、年龄、风格偏好**，给出上衣、内搭、裤子、鞋子
* 一句“为什么这样穿”的解释：按当天实际情况逐条说明（温度带、温差、雨雪、大风、年龄等）
* 特殊天气提醒（下雨带伞、大风穿挡风外套、早晚温差加减衣服、高温防晒）
* **AI 模特试穿**：点一下按钮，生成一张穿着这套搭配的男 / 女模特插画（可「收起」、可「换一张」）

天气数据拿不到时会用**按季节推算的兜底方案**，保证任何情况下都能给出一套不出错的穿搭。点天气卡片上的城市名，还能**手动切换城市**。

### 2. 每日穿搭打卡

* 首页点击「记录今日穿搭」，拍照或从相册选图完成打卡
* 打卡成功后触发**双重弹窗**：先弹出上传成功提示（1.5 秒后缓缓淡出），紧接着弹出随机鼓励语（放大动画，点击「确定」关闭）
* 当日打卡后按钮变为「今日已打卡」并禁用，次日恢复可打卡
* 打卡记录与照片存于**云端**，换设备不丢失

### 3. 个人每日风采库

* 以**瀑布流照片墙**展示历史打卡的照片、日期、当天天气与穿搭摘要
* 支持**管理批量删除**：点「管理」→ 勾选不要的照片 → 点「删除」→ 二次确认（照片不可复原）

### 4. 搜索（接大模型）

搜索框默认填写：

> 这个季节穿啥衣服

用户搜索后，由大模型返回温和、具体、不评判的回答。提问时会自动带上**你所在城市的实时天气**和**你的性别 / 年龄 / 风格偏好**，回答上方会显示「已结合 XX 实时天气 · XX 偏好」，让建议更贴合你本人，而不是千人一面。

提示词面向的用户画像是：

> 刚高考完，因为家庭和环境的原因，没有基本穿衣常识的年轻人。

回答会引导用户一步步学会穿衣搭配，而不是只给一个结果。

搜索历史会保存在本地（最近 20 条），点击可展开查看当时的完整回答，也可一键清空。

### 5. 我的（个人信息）

* 个人信息：昵称、年龄、性别、**风格偏好**（简约基础 / 休闲运动 / 温柔甜美 / 商务通勤 / 文艺复古），提供**查看 / 编辑两种模式**，编辑后保存到本地
* 「个人每日风采库」入口，右侧显示「已打卡 X 天」（累计天数）
* 底部有一句鼓励的话：

> 穿衣搭配没有想象中那么难。我曾经也不会，但慢慢就学会了。

还有一个反馈按钮，用户点完可以留下意见。

### 6. 贴心引导（不打扰）

* **定位**：首次进入自动定位一次；若没有定位权限，弹窗提示，并引导**手动选择城市**（省份 → 城市两级）——不依赖定位也能用
* **资料**：若还没填写基本信息，弹窗温和引导「填写后会为你个性化推荐」，并提供**跳过**按钮；跳过或填写后都不再重复打扰

## 设计原则

* **不评判**：不问“你怎么连这个都不知道”，而是说“很多人一开始都不懂，这很正常”。
* **给兜底**：不确定的时候，永远有一个最简单的安全方案（天气拿不到就按季节推算）。
* **解释为什么**：不只给结果，还要告诉用户“为什么这样穿不会错”。
* **极简**：不搞衣橱管理，不搞社交，打开即用、用完即走。**穿什么由确定性规则决定**（不是让 AI 替你决定穿搭）；AI 只用来把已经定好的搭配，画成一张「模特试穿」的插画。

## 技术栈

* 微信小程序原生开发 + TypeScript
* 微信开发者工具
* 后端：微信云开发（云数据库 + 云存储 + 云函数）
* 天气 API：高德开放平台（定位逆地理编码 + 实况天气 + 预报），经云函数代理
* 大模型 API：阿里云百炼 DashScope（OpenAI 兼容接口，模型 `deepseek-v4.1-flash`），经云函数代理
* 生图 API：通义万相（DashScope，模型 `wanx2.1-t2i-turbo`），经云函数代理
* 数据存储：打卡记录、风采库、生图缓存存云数据库 / 云存储；个人信息、搜索历史、所选城市存本地
* Git / GitHub 版本管理

### 前后端划分

| 层 | 位置 | 职责 | 现状 |
|---|---|---|---|
| **前端** | `miniprogram/` | 页面渲染、穿搭规则引擎、数据服务封装 | 已完成 |
| **后端** | `cloudfunctions/` + 云开发 | 数据持久化、文件存储、第三方 API 代理（隐藏密钥） | 5 个云函数 + 4 个集合 + 云存储 |

**数据流**：

- 打卡记录 → 云数据库 `checkin_records`；打卡照片 → 云存储
- 风采库列表 / 批量删除 → 读取、删除 `checkin_records` 与云存储文件
- 鼓励语 → 云数据库 `encouragement_library`（读不到时用内置 10 条兜底）
- 天气 → 云函数 `getWeather`（高德 Key 保存在服务端）
- 大模型问答 → 云函数 `askLLM`（DashScope Key 保存在服务端）
- 模特试穿图 → 云函数 `genOutfitImage` 生图并存入云存储，缓存记录存 `outfit_images`
- 用户反馈 → 云函数 `submitFeedback` → 云数据库 `feedback`
- 个人信息、搜索历史、所选城市 → 本地存储

## 运行说明

1. 从浏览器下载并安装「微信开发者工具」：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
2. 打开微信开发者工具，点「导入项目」，目录选择项目根目录 `项目-小白穿衣推荐`（即含 `project.config.json` 的那一层）
3. 开通云开发（如未开通）：微信开发者工具点「云开发」→ 开通并创建环境，将环境 ID 填入 `miniprogram/utils/config.ts` 的 `CLOUD_ENV`
4. 部署 5 个云函数：在文件树分别右键 `cloudfunctions/` 下的 `initData`、`getWeather`、`askLLM`、`genOutfitImage`、`submitFeedback` →「**上传并部署：云端安装依赖**」
5. 配置云函数环境变量（云开发控制台 → 云函数 → 对应函数 → 配置）：
   - `getWeather` → `AMAP_KEY`：高德开放平台的 **「Web 服务」类型** Key
   - `askLLM` → `DASHSCOPE_KEY`：阿里云百炼 Key（可选 `LLM_MODEL` 覆盖模型名）
   - `genOutfitImage` → `DASHSCOPE_KEY`（同上，可与 `askLLM` 同一个），并把该函数的**超时时间调到 60 秒**（生图较慢）
6. 设置数据库权限（云开发控制台 → 数据库）：
   - `checkin_records` →「仅创建者可读写」
   - `outfit_images` →「仅创建者可读写」
   - `feedback` →「仅创建者可读写」
   - `encouragement_library` →「所有用户可读」
7. 定位权限：`getLocation` 需在小程序后台**申请「地理位置」接口权限**；未申请或用户未授权时，小程序会自动引导用户**手动选择城市**，不影响使用
8. 编译运行（启动时 `app.ts` 会自动调用 `initData` 创建集合并写入文案）

## 上线说明

1. 开发者工具点右上角「**上传**」，填写版本号（如 1.0.0）
2. 小程序后台（mp.weixin.qq.com）→「管理」→「版本管理」→ 提交审核
3. 提交前需完成：**用户隐私保护指引**（声明位置信息、摄像头、相册用途），必要时申请**定位接口权限**
4. 审核通过后点「发布」

## 已知限制

* 打卡数据与照片存**云端**，换设备、清缓存都不会丢失；云开发为付费服务，体验版额度有限，超出需按量付费
* **AI 模特试穿按次计费**：已按「日期 + 性别 + 年龄 + 风格」缓存，同一天同一画像只生成一次；「换一张」会重新生成并删除旧图，避免云存储堆积
* 天气与大模型的 API Key 保存在**云函数**中，前端不包含任何密钥；建议在云开发控制台为云函数配置「环境变量」，代码中只保留占位默认值
* 定位接口权限未批时，手动选择城市是官方兜底路径；城市数据覆盖 34 个省级行政区的主要城市
